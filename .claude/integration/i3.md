# I3 · panel — integración

Rama `agente/i3`. Fase 0, tareas 1 y 2 del brief: esqueleto del panel con la identidad Horus,
inicio de sesión con MFA y menú por permisos.

## Lo que entrego

- **`apps/web` (`@iris/web`):** Next.js 15.5 (App Router), React 19, Tailwind 4, TypeScript
  estricto. Rutas: `/entrar` (login + MFA), `/` (inicio), `/usuarios` (solo lectura, cursor),
  y «Próximamente» en `/tickets`, `/ordenes`, `/agenda`, `/despacho`, `/comercial` y
  `/administracion`. Tema claro/oscuro/sistema (`next-themes`, clase `.dark`), favicon =
  `docs/marca/logo-mark.svg`, aura + vidrio en barra lateral y superior + tarjetas.
- **Sesión** según `i1.md`: `POST /sesion` → `mfaRequerido` → `POST /sesion/mfa`; 401
  `credenciales_invalidas`, 401 `codigo_invalido` (sigue en MFA), 401 `mfa_bloqueado` y
  `no_autenticado` (vuelve al login), 429 `demasiados_intentos` con «Demasiados intentos, espera
  N min» desde `Retry-After` y el botón bloqueado hasta que pase; 422 → errores por campo.
  `DELETE /sesion` para salir (un 401 cuenta como salida). `GET /yo` fallido → error con
  «Reintentar» y sin menú; 401 → `/entrar?motivo=expirada`.
- **CSRF:** el cliente (`lib/api/cliente.ts`) añade `X-CSRF-Token` con la cookie `iris_csrf` en
  todo método distinto de GET/HEAD/OPTIONS; `credentials: "include"`.
- **Proxy same-origin:** `app/api/[...ruta]/route.ts` reenvía `/api/*` a `IRIS_API_URL` (leída en
  ejecución; documentada en `.env.example` y `apps/web/.env.example`), con todas las `Set-Cookie`,
  `Retry-After`, `X-Forwarded-Host/Proto`, y 502 `api_no_disponible` si la API no responde.
  Probado con el build `standalone` contra la API Go real (`iris servir` + `admin crear`):
  credenciales inválidas, login, cookies HttpOnly/CSRF, menú, usuarios, cerrar sesión y el 429
  al 11.º intento con «espera 15 min». En `standalone` usa `HOSTNAME=0.0.0.0` (como el compose):
  con `HOSTNAME=127.0.0.1` Next reescribe el `Location` de las redirecciones a `localhost`.
- **Middleware:** sin cookie `iris_sesion` → `/entrar?siguiente=<ruta>` (Location relativa). No
  cubre `/campo`, `/soporte`, `/entrar` ni `/api`.
- **Menú por permisos** (`lib/menu.ts`) con el tipo `Schema<"Permiso">`: Usuarios →
  `usuarios.ver`; Administración → `tokens.ver | roles.ver | permisos.ver`. Una prueba verifica que
  todos los nombres existen en el enum del `openapi.json`.
- **`apps/web/Dockerfile`** (standalone, `PORT=3000`, contexto la raíz) +
  `Dockerfile.dockerignore`. No pude construir la imagen aquí (sin demonio Docker).
- **Pruebas:** Vitest (cliente/CSRF, problem+json, Retry-After, esquemas zod, menú, proxy,
  favicon) y Playwright en 4 proyectos (escritorio 1280 / teléfono 390 × claro / oscuro): login,
  validación, credenciales inválidas, 429, MFA (con CSRF), MFA bloqueado, redirección sin sesión,
  sesión vencida, cerrar sesión, menú filtrado, sin permiso, Próximamente, `/yo` fallido +
  Reintentar, usuarios con cursor y error + Reintentar, selector de tema.

## `packages/ui` (`@iris/ui`) — disponible para I4

Importa `@iris/ui/estilos.css` después de `tailwindcss` y agrega `@source` hacia
`packages/ui/src` (ver `packages/ui/README.md`). Componentes: `Boton` (`asChild` para `Link`),
`Entrada`, `Etiqueta`, `Campo`, `Tarjeta*`, `Aviso` (con `accion` para «Reintentar»),
`InsigniaEstado` (icono + texto + color), `EstadoVacio`, `Esqueleto`, `Cargando`,
`GrupoSegmentado`, `Hoja*`, `Tabla*`, `LogoIris`, `MarcaIris`, `cn`, y el tipo `Tono`.
Si necesitas otro componente (p. ej. `Select`, `Textarea`, `Casilla`), pídemelo aquí o agrégalo en
`packages/ui` en una PR coordinada: ESLint de `apps/web` prohíbe `<button>`, `<input>`, `<select>`
y `<textarea>` crudos. El cliente `crearClienteIris()` / `resolver()` / `ErrorApi` vive en
`apps/web/lib/api/` y lo puedes usar desde `app/campo`; si lo prefieres en un paquete, lo movemos.
