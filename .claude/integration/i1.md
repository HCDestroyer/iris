## Lo que entrego

### Base de casos de uso (para I2)

Paquete `internal/auditoria`. Un caso de uso es un `*auditoria.Caso[In, Out]` armado con
`auditoria.Nuevo` (en una variable del paquete o en el constructor del módulo) y ejecutado con
`Ejecutar(ctx, in) (Out, error)`:

```go
var Escalar = auditoria.Nuevo(auditoria.Caso[EntradaEscalar, Ticket]{
    Accion:  "tickets.escalar",                // nombre de la acción = permiso
    Logica: func(ctx context.Context, t *auditoria.Tx, in EntradaEscalar) (Ticket, error) {
        q := soportebd.New(t)                  // *auditoria.Tx embebe pgx.Tx: sirve a sqlc
        t.FijarEmpresa(ticket.EmpresaID)       // multiempresa (si no, la del contexto)
        t.RegistrarCambios("ticket", id, antes, despues)
        if err := t.Emitir("ticket.estado_cambiado", payload); err != nil { return Ticket{}, err }
        return …, nil
    },
})
```

- **Qué hace `Ejecutar`:** transacción (`nucleo.EnTx`; si ya hay una en `ctx`, savepoint) →
  permiso del actor (anónimo 401, sin permiso 403) → `Logica` → `auditoria.acciones` y
  `auditoria.cambios` → COMMIT con los eventos del outbox. Si falla, ROLLBACK (sin eventos) y la
  fila de error se escribe en otra transacción. Los ganchos `t.AlConfirmar(fn)` corren tras el
  COMMIT más externo.
- **`Acceso`:** `ConPermiso` (defecto; `Permiso` vacío = `Accion`), `Autenticado`, `Publico`.
- **`AuditarExito func(Out) bool`:** como en Argos; `nil` = siempre. Para lecturas. Si hubo
  cambios registrados, la fila se escribe igual; los errores se auditan siempre.
- **Sensible:** por nombre (`contrasena`, `token`, `hash`, `secreto`, `totp`, `firma`, `csrf`,
  `credencial`…; nunca `*_id`) o con la etiqueta `auditoria:"sensible"` en el campo → `***` en
  la entrada y en los cambios. `created_at`, `updated_at` y `version` no se registran como cambio.
- **Errores:** devuelve `*nucleo.Problema` (`nucleo.NoEncontrado`, `ReglaNegocio(codigo, detalle)`,
  `Validacion(campos…)`, `Conflicto`, `ConflictoVersion`, `Prohibido`). `pgx.ErrNoRows` → 404,
  unique → 409, FK/check → 422, el resto → 500 sin filtrar el mensaje (`nucleo.AProblema`).
- **`version` → 409:** `UPDATE … WHERE id = @id AND version = @version RETURNING *` y
  `nucleo.VerificarVersion(err, "ticket", id)`; o `nucleo.ExigirVersion` tras un `FOR UPDATE`.
- **Paginación:** embebe `nucleo.ParamsPagina` en la entrada; consulta `id > @despues_de … LIMIT
  @limite` con `Limite()+1`; `nucleo.DecodificarCursor` y `nucleo.Paginar(filas, limite, convertir,
  clave)` → `nucleo.Pagina[T]{data, nextCursor}`.
- **Alcance:** `contexto.PermisosDe(ctx).Alcances("tickets.ver")` → `global, zonas, cuadrillas`
  para filtrar.
- **Handlers (huma):** registra rutas con `huma.Register` en una función `func(huma.API)` y pásala
  en `servidor.Deps.Modulos`. Embebe `nucleo.ConIdempotencia` en las entradas que cambian estado
  (documenta la cabecera; el middleware ya la aplica). Ejemplo completo en
  `internal/nucleo/identidad/rutas.go`. Agrega `x-permiso` como ahí.
- **Permisos nuevos:** constante + línea en `nucleo.Catalogo` (orden alfabético) y, si aplica, en
  `nucleo.RolesBase`; `go run ./cmd/iris migrar` los sincroniza. `auditoria.Nuevo` entra en pánico
  si el permiso no existe. Toca `permisos.go` en una PR coordinada conmigo (es de I1).
- **Suscriptores internos:** `bus.Suscribir("soporte.algo", "orden.cerrada", fn)` en
  `cmd/worker`; reciben actor sistema, canal worker y el request id del emisor; deben ser
  idempotentes. Un error reintenta el evento (5 s, 10 s, … hasta 1 h).
- **Workers propios:** `integracion.OpcionesWorker.Registrar(func(*river.Workers))`.
- **Pruebas:** `func TestMain(m *testing.M) { os.Exit(pruebas.Correr(m)) }` y usa `IRIS_DB=iris_test_i2`.
  `pruebas.ContextoSistema(pool)`, `pruebas.ContextoUsuario(pool, id, permisos…)`,
  `pruebas.Correo("x")`. Usa un paquete `_test` externo.
- **Migraciones:** `make -C apps/api migracion NOMBRE=soporte_tickets` (goose, marca real). Las
  de I2 van en el mismo `apps/api/migraciones/` (goose usa un solo directorio); sqlc: agrega tu
  entrada en `apps/api/sqlc.yaml` copiando una de las existentes.

### Identidad (endpoints)

`POST/DELETE /api/v1/sesion`, `POST /api/v1/sesion/mfa`, `GET /api/v1/yo`,
`POST /api/v1/yo/mfa` y `/yo/mfa/activar`, `GET/POST /api/v1/usuarios`,
`POST /api/v1/usuarios/{id}/editar` y `/desactivar`, `GET /api/v1/roles`, `GET /api/v1/permisos`,
`GET/POST /api/v1/tokens`, `POST /api/v1/tokens/{id}/revocar`, `GET /api/v1/salud` y `/listo`.

Para I3: la cookie `iris_sesion` es HttpOnly; `iris_csrf` no, y su valor (también en
`csrfToken` del login) va en `X-CSRF-Token` en toda petición que cambie estado. Con MFA,
`mfaRequerido: true` y luego `POST /sesion/mfa`. La app de campo y el portal mandan
`X-Iris-Canal: campo|portal`. `GET /yo` da `permisos` (enum `Permiso` del OpenAPI).
